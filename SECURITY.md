# Security Policy

## Reporting a vulnerability

Do not disclose security vulnerabilities in public issues, discussions, pull requests, logs, or chat transcripts.

Use GitHub's private vulnerability reporting for the affected repository when it is available. Otherwise, open a private security advisory in the relevant repository and include:

- the affected repository, revision, and environment;
- the vulnerable behavior and expected security boundary;
- a minimal reproduction or proof of concept;
- the likely impact;
- any known mitigation.

Remove credentials, access tokens, private keys, personal data, and production data from every report.

## Response expectations

The maintainers will validate the report, determine affected contracts and versions, and coordinate remediation and disclosure. Public disclosure should wait until a fix or documented mitigation is available.

## Supported versions

0xda-market is under active development. Security fixes target maintained default and release branches according to the affected repository's documented support policy.
